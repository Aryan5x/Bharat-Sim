00

What it is

BharatSim is a cloud test lab that shows how an Android app behaves on the phones and networks most Indians actually use. A developer uploads an APK. We run it on a real Android emulator set up like a budget phone (2 GB RAM, 720p, low storage) on 2G, 3G, congested or dropping networks, and run it again on a normal baseline. It explores the app automatically, and ML classifies the crashes, freezes, jank, slow starts and network failures. Developers get a report they can fix from, and founders get the same verdict in Hindi or other Indian languages, with a voice summary. No device lab to buy.

Real constraints on the emulator

  • Low-end device: 2 GB RAM, Android 11 (ARM translation, so real APKs install), 720p screen, low free storage
  • Indian network profiles: rural 2G, crowded-station 3G, congested 4G, calibrated to TRAI MySpeed data
  • Flaky network: a metro-tunnel drop and recovery mid-session. Battery saver: on

What we measure

  • Cold-start time, and UI jank (slow frames from gfxinfo)
  • Crashes, ANRs, network errors and timeouts
  • Offline handling: crash, freeze or error, plus recovery time
  • Memory, and mobile data used per session

Report

  • Bharat Readiness Score, with every point linked to its evidence
  • Pass, warn or fail per profile against baseline, with logcat evidence and a fix
  • Shareable link, PDF and JSON export

ML and exploration in the core flowscikit-learn, adb

  • Failure classifier: TF-IDF + linear model trained on LogHub Android logs and our runs. It labels crash, ANR, out-of-memory, network or storage, with a confidence score
  • Anomaly detection: statistical tests and IsolationForest on baseline vs constrained runs flag real regressions, not noise
  • Exploration: automated taps through the app with adb monkey find failures beyond the launch screen

Backend and reliability

  • Supabase Postgres with row-level security, private APK storage, no faked steps
  • Sample APK for evaluators. A fast default run (baseline + 1 profile), with the full suite optional
  • Clear errors and rate limits. Live on Vercel

Stretch goals, only if time allows (not promised): Hindi voice Q&A about a report using Sarvam speech-to-text, a CI webhook, and a Neo4j failure-similarity graph

Definition of done

An evaluator can sign in on our live URL, upload an APK, run it on a cheap-phone profile on a real constrained emulator, and get a genuine, ML-classified report against a baseline run, without our help. The report covers crashes, launch time, network failures and a voice summary, in English or an Indian language.
