Problem statement T1.2: The Cheap Phone Test

BharatSim is a cloud test lab for Android apps. A developer uploads an APK, picks a Bharat persona, and BharatSim runs it on a real budget-phone emulator under Indian network conditions and on a normal baseline. It then reports crashes, freezes, jank, slow starts and connectivity failures with log evidence, a Bharat Readiness Score, and an explanation in Indian languages. We are building on our submitted prototype, not starting a new idea.

  1. Where you are: what works in the prototype today, and what is mocked, hardcoded or missing (live build checked 21 Nov, 14:46 IST).
    Works
    • 4 Bharat personas and a category-aware risk planner, with the Interaction Hunter (pairwise condition hypotheses)
    • Failure DNA: logcat paste analysis with rule-based fingerprints, secret redaction and a heuristic BharatScore
    • APK zip and size checks, a lease-based worker protocol, and an ADB smoke runner proven in CI on a fixture app
    • React dashboard, FastAPI backend, optional Supabase Auth code
    Mocked, hardcoded or missing
    • No database on the live build (database: unavailable), so uploads, runs and history are off
    • No worker is connected, so no real execution happens live
    • Auth is not verified end to end; Sarvam is disabled
    • Scores are hardcoded rules, with no ML, no baseline comparison and no anomaly detection
    • Packet loss and CPU limits are unsupported; there is no PDF report, sharing or evaluator walkthrough
  2. Where you will be: the exact features, flows and integrations working by 12 PM on 22 November.
    • Primary flow, live end to end: sign up or sign in (Supabase Auth, password recovery) → drag-and-drop APK upload into private storage (signature, structure and size checks; package, version and min/target SDK extracted) → pick a persona → the job is queued → a worker runs it on a real Android 11 emulator (2 GB RAM, 720p) → live stages → a report comparing baseline and constrained runs
    • Personas applied for real:
      • Budget Android: 2 GB RAM, Android 11, 720p, battery saver, low storage
      • Edge Village: about 450 ms latency, about 8% loss emulated as TCP retransmission stalls and resets, restricted bandwidth
      • Crowded Station: congested 3G
      • Congested Urban 4G: variable bandwidth with dropouts
      Shaping runs through a measured host-side proxy (EDGE verified at 480 kbps in testing), with an airplane-mode drop and recovery
    • Telemetry (adb, dumpsys, gfxinfo, logcat), each value tied to its run and timestamp:
      • cold start and time to first frame
      • jank and frame time
      • crashes, ANRs and OOMs
      • memory
      • network failures, timeouts and recovery time
      • data transferred
      Automated exploration runs adb monkey restricted to the app
    • ML (scikit-learn):
      • a TF-IDF + logistic regression failure classifier (crash, ANR, OOM, network, storage), trained by scripts/train_classifier.py on LogHub Android logs with versioned models and real held-out metrics
      • baseline-vs-constrained anomaly detection (z-score/IQR plus IsolationForest)
      • a transparent Bharat Readiness Score with category scores and evidence links
    • Reports: PDF and JSON export, secure share links, history and comparison; a clearly labelled evaluator walkthrough with two scenarios (UPI checkout timeout; quick-commerce OOM)
    • Security, deployed on Vercel with a Supabase backend: row-level security and tenant isolation, signed URLs, rate limits, CSP, audit log, worker token auth; ArgosX baseline scan by midnight, final scan by 11 AM, with a remediation log

  4. Your partner tech choice: Sarvam AI, deepened from an optional, disabled translation into every report. Product need: Bharat's users and many of the people who decide whether to ship are not English-first, and a test report only helps if the decision-maker understands it. In the core flow, visible in the demo:
    • the Sarvam LLM (sarvam-105b) turns ML-classified findings and evidence into what happened, why, user impact and fixes
    • Sarvam Translate renders the full report in Hindi, Tamil and Marathi, keeping technical identifiers
    • Sarvam Bulbul TTS plays it as audio
    All three were verified live with our key on 21 Nov.
  5. Your definition of done: an evaluator can open our live URL, sign in, upload an APK, run it on a Bharat persona on a real constrained emulator, and get a genuine, ML-classified report against a baseline run, with evidence, a readiness score, and a Sarvam explanation they can read and hear in Hindi, without our help.
Honest scope notes:
  • The emulator worker runs on our team laptop and connects to the live API, because Vercel cannot host emulators
  • Emulator console throttling did not slow TCP traffic in our tests, so shaping is enforced by a measured proxy
  • Network presets follow documented emulator values (EDGE, UMTS) rather than "TRAI-calibrated" figures until a cited field source is added
  • Stretch: an Android companion app, a Neo4j failure graph and a CI webhook
